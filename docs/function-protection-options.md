**状態: 調査のみ。実装・設定変更は一切していません。** 家主の判断を待ちます。`GITHUB_TOKEN` の導入、認証機能、外部データベース、有料サービスの追加は今回の対象外です。

区分: **公式ドキュメント（検索結果の要約）**=Netlify の公式ページを検索して得た記述（このプロジェクト上では動作確認していない）、**推測**=私の見積もり、**未確認**=確認できていない。ドキュメントは更新されるため、採用前に最新の公式ページとダッシュボードで確認してください。

## 現状のリスク（再掲）
`/api/github-snapshot?repo=<許可リポジトリ>` は認証なしで誰でも呼べます。1回の呼び出しで GitHub に4リクエスト。未認証の GitHub 上限は 60回/時間で、Netlify の送信元 IP 単位で数えられると推測しています（共有かどうかは未確認）。上限に達すると、家主自身の同期が一時的に失敗します。許可リスト外のリポジトリは 403 で、漏れる情報は公開データのみです。応答は現在 `Cache-Control: no-store` で、すべての呼び出しが GitHub まで届きます。

## Netlify の利用枠・費用への影響
- 公式ドキュメント（検索結果の要約）: 新しい料金体系はクレジット制で、Free は月300クレジットのハードリミット（超えると費用は発生せず、次の請求サイクルまでプロジェクトが停止）。Functions はコンピュートとして 10クレジット/GB・時間を消費。旧体系（2025年9月4日以前に作成したプロジェクト）では Function 呼び出し 125,000 回/月の記載があり、**どちらの体系が家主のサイトに適用されるかは未確認**。
- 見積もり（**推測**。前提: 1回の実行が約1秒、メモリ 1 GB。実際のメモリ設定・実行時間は未確認）: 1呼び出し ≒ 0.003 クレジット。300クレジットで約10万回の呼び出し相当。悪用でこれを使い切ると、Free ではサイトが停止し得る（費用は発生しない）。有料プランで自動チャージを有効にしている場合は費用が発生し得る。
- 実測値は取得していません。家主の Netlify ダッシュボードの Usage で、現在の消費量とプランを確認してください。

## 推奨（家主の承認が必要）
1. **まず #1（CDN キャッシュ）**: 小さな変更で、GitHub 上限の消費と Function 実行を同時に減らせる。手動同期が最大60秒古くなることを受け入れられるかを判断してください。実装する場合は、Netlify のプレビューで「ヒット時に Function が実行されないこと」「エラー応答がキャッシュされないこと」を実測してから採用する。
2. **#3 の可否を確認**: 家主のプランで「プロジェクトの非公開」等が追加費用なしで使えるなら、第三者がアクセスできなくなる最も確実な対策。プランと費用の確認が先。
3. **#2 は保留**: プラン対応と挙動をプレビューで確認できるまで採用しない。採用する場合は 429 の画面表示を補う小改修を伴う。
4. **#4（トークン）は導入しない**（指示どおり）。必要になった時点で再検討。
5. 当面の運用: ダッシュボードで利用量を確認する。この対策案はいずれも**未実装**で、v0.1 の既知の制約（M-4）として残ります。
