# AI Dev Control v0.1 ユーザーガイド

データはこのブラウザの localStorage にだけ保存されます。ブラウザのデータ消去や別のブラウザ・端末では引き継がれません。**定期的に「データ管理」からバックアップをダウンロードしてください。**

## 1. はじめに（最初の設定）
1. 「担当者」で担当者を登録（名前・種別・役割を1つ以上）。
2. 「プロジェクト」でプロジェクトを登録。GitHub 連携する場合は `owner/name`（または GitHub の URL）を入力。公開リポジトリのみ対象です。
3. 「タスク」でタスクを追加し、担当者やプロジェクトを選びます。

サンプルデータはありません。表示されるのはすべて自分で入力した実データです。

## 2. 画面ごとの操作
- **ダッシュボード**: プロジェクト数、作業中、家主の承認待ち、ブロック中、担当者ごとの状況、最近の GitHub 活動、最終同期日時。
- **プロジェクト**: 登録・編集・削除。削除すると関連タスクと作業時間も消えます（確認画面に件数が出ます）。**リポジトリを別のものに変更すると**、確認画面に影響するタスク数が表示され、確定すると、そのプロジェクトのタスクの **Issue/PR の紐付けはすべて解除**されます（旧リポジトリの番号は引き継ぎません）。家主承認済みのタスクは紐付けが変わるため承認が取り消され「承認待ち」に戻ります（再承認が必要）。旧リポジトリの GitHub データも破棄されます。キャンセルすると何も変わりません。大文字・小文字だけの違いは同じリポジトリとして扱い、解除しません。リポジトリが未設定のプロジェクトに初めて設定するときは、すでに入力した番号は残ります。
- **タスク**: 未着手／作業中／レビュー中／承認待ち／完了／ブロック中の6列。状態は各カードの選択欄で変更します。「完了」は選べません。
  - **家主の承認**: 「承認待ち」のカードで「承認する」→確認画面で確定すると「完了」になります。承認は人間の操作でのみ記録されます。
  - 承認済みタスクのタイトル・メモ・プロジェクト・Issue/PR番号を変えて保存すると、承認が取り消されて「承認待ち」に戻ります（保存前に警告と確認が出ます）。担当者だけの変更では取り消されません。
  - カードの「GitHubの状態」は Issue/PR の状態（マージ済みなど）、「家主の承認」は人間の承認で、**別のものです**。PR がマージ済みでも承認済みにはなりません。
  - 作業時間が記録されているタスクは、**別のプロジェクトへ移動できません**（編集画面に理由が表示されます。作業時間は自動では移動・削除されません）。先に作業時間を整理してください。
  - Issue/PR との紐付けは番号の**手入力**です。「最新30件に見つかりません」は、古くて取得範囲外の場合に出ます。
- **作業時間**: 「作業日＋所要時間（分）」または「開始・終了日時」で手入力。日付なしでも登録できますが、日付なしの記録は「今日・今週・今月」の集計に含まれず「全期間」にだけ入ります。週は月曜始まり、判定はブラウザの時間帯です。GitHub の履歴から時間を推測することはありません。
- **GitHub連携**: 「手動で同期」を押したときだけ取得します（Issue・PR・Commit 各最新30件）。API 残量と最終取得日時を表示します。**同期に失敗しても前回のデータは消えません**（失敗理由が表示されます）。同期は1回あたり GitHub に4回問い合わせるため、未認証だと1時間に約15回までです。
- **担当者**: 追加・編集・削除。編集しても既存のタスク・作業時間との紐付けは保たれます。作業時間の記録がある担当者は削除できません。削除前に確認画面が出ます（担当タスクは「未割り当て」になります）。作業時間の削除にも確認画面が出ます。

## 3. バックアップと復元（データ管理）
- **バックアップ**: 「JSONをダウンロード」。プロジェクト・担当者・タスク・作業時間が入ります。GitHub から取得したデータは含まれません（再同期で取得できます）。
- **復元**: 「バックアップから復元」でファイルを選ぶと、内容を検証して確認画面（現在と復元後の件数）が出ます。「復元する」を押すまで何も変わりません。現在のデータは置き換わるので、先にバックアップを取っておくと安全です。形式が不正なファイルは拒否され、現在のデータは変更されません。**参照が壊れている**（存在しないプロジェクト・担当者・タスクを指している、プロジェクトが食い違っている）ファイルや、**同じ ID が重複している**ファイルも、復元前に拒否されます（「復元できません: integrity check failed…」。現在のデータは変更されません）。旧形式（v1）のバックアップも復元できます。

## 4. 複数タブと「古いデータ」の警告
同じブラウザで複数のタブを開いて使うと、先に保存したタブのデータを後のタブが上書きしないよう、**古いタブでは編集と保存が止まります**。
- 画面上部に「このタブのデータは古くなっています」と出たら、「最新のデータを読み込む」を押してください。
- そのタブで直前に入力していた内容は保存されていません。再読み込み後にもう一度入力してください。
- 迷う場合は、再読み込みの前に「データ管理」からバックアップをダウンロードできます（そのタブが持っている古い内容になります）。
- **制約**: 2つのタブがまったく同じ瞬間に保存した場合までは、ブラウザの仕様上、防げると保証できません。1つのタブで使うことを推奨します。

## 5. 保存に関する警告と対処
| 表示 | 意味 | 対処 |
|---|---|---|
| 保存できませんでした（容量など） | 保存に失敗。直前のデータは保持（または書き戻し済み） | バックアップをダウンロードし、不要なデータを減らすかブラウザの空き容量を確保 |
| 直前のデータへの復旧にも失敗 | 画面のデータは残っているが保存先は不確実 | **すぐにバックアップをダウンロード**し、ブラウザを再読み込みして内容を確認 |
| 既存データを読み取れなかったため保存を中止 | 保存先を読めず上書きを避けた | 再読み込み。改善しなければバックアップを取得 |
| 読み取り専用モード | 保存データが新しいバージョンのアプリで作られている | アプリを最新版に更新。編集・復元はできません |
| 保存データを読み込めませんでした | データが壊れている | 「データ管理」で「保存データ（生）をダウンロード」して保管→バックアップから復元、または「空の状態で開始」。「空の状態で開始」「復元」では、壊れた元データがブラウザ内に控え（`adc:corrupt-copy:*`）として自動的に残ります。控えを作れない場合は元データを上書きせず中止します |
| 保存データに整合性の問題があります | 保存済みのデータに、存在しない項目への参照や重複 ID がある（自動では修正・削除しません） | 「データ管理」でバックアップを保管し、一覧の項目を手動で整理 |
| 他のタブが新しいデータを保存していたため、書き戻しは行わなかった | 保存の確認中に別のタブが保存した。そのデータを守るため上書きしなかった | 「最新のデータを読み込む」で再読み込み。直前の入力は保存されていないので再入力 |
| 保存先を読み取れないため、書き戻しは行わなかった | 保存結果を確認できない | バックアップをダウンロードしてから再読み込み |
| 直前の世代のデータから復旧しました | 最新の保存が読めず、ひとつ前の内容を表示 | 直近の変更が抜けている可能性。内容を確認 |
| 旧形式のデータを新形式に変換して表示 | v1 データを読み込んだ（まだ保存していない） | 最初の保存時に変換前の元データが `adc:premigration:v1` として控えられます |
| 旧形式のデータを変換できませんでした | 変換不能。元データは無変更 | 「保存データ（生）をダウンロード」で保管 |
| ブラウザの保存領域が使えません | プライベートモード等 | タブを閉じると消えます。こまめにバックアップ |

## 6. 既知の制約（利用上）
- 認証はありません。画面の URL を知る人は誰でもアプリを開けますが、データは各自のブラウザ内にのみ存在します。
- GitHub は最新30件のみ。ページングや差分取得はありません。
- 自動同期・自動マージ・Issue/PR の作成はできません。
- 詳細は [release-notes-v0.1.md](release-notes-v0.1.md) と [review-v0.1.md](review-v0.1.md) を参照。
